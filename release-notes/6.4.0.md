## Before you upgrade (TEMPERATURECONTROL only)

- An OFF thermostat now shows as `off` in Home Assistant, without a target
  temperature. It used to show its last mode, so check automations and
  dashboards that rely on that.
- A command with `"state": "ON"` and a mode, preset or fan speed now switches
  an OFF thermostat on. Home Assistant always sends that state, so
  `set_fan_mode` on an OFF zone turns it on too.
- The eco offset is now reported as unsigned. Negative offsets are untested
  and would show as a high value.

No configuration changes are needed.

## New

- Home Assistant presets via `ha_preset_modes`, including your own labels and
  a `MANUAL` preset (off by default)
- `hvac_action` (heating / idle / off) via `ha_hvac_action` (off by default,
  only observed on a heating-only MICROS+)
- `ha_min_temp`, `ha_max_temp` and `ha_fan_modes`
- Change the day and night preset temperatures and the eco offset over MQTT
  (`DAY_PRESET`, `NIGHT_PRESET`, `ECO_OFFSET`)

## Fixed

- State messages no longer fail for thermostats that report no preset, mode
  or fan speed (e.g. radiator zones)
- A mode, preset or fan speed chosen while the thermostat is OFF is no longer
  lost
- Out-of-range temperatures are rejected instead of wrapping around
- The bridge and sensor 1 no longer clash on the same entity id. New
  installations get a different bridge entity id.
