## Before you upgrade

This release contains a large internal cleanup of the code base, driven by
SonarQube and backed by many new tests. The cleanup itself is not meant to change
any behaviour: MQTT topics, Home Assistant discovery payloads and the keys of
`config.json` stay the same, and no configuration changes are needed.

One value changes on MQTT: for `TEMPERATURECONTROL` sensors, `window_open`,
`output_state` and `swing_direction` now report 255 instead of -1, as
documented. Check automations that compare these to -1.

Still, a lot of code was touched, so something may behave differently without
us knowing. The parts that changed most:

- Reading the messages and events that the central unit sends
- Reconnecting to the central unit and stopping the bridge
- Display messages
- The Home Assistant discovery config of sensors
- The container health check

If something no longer works as before, please open an issue and mention the
version you came from. Going back to 6.4.0 is a safe way out in the meantime.

## New

- TLS to the MQTT broker: set `TELETASK_MQTT_SSL=true` (usually with
  `TELETASK_MQTT_PORT=8883`). The broker's certificate must be trusted and its
  name must match `TELETASK_MQTT_HOST`. For a broker with its own CA, point
  `TELETASK_MQTT_CAFILE` at a PEM file with that CA and mount it into the
  container.

## Fixed

- Events from the central unit that arrived split over two network reads were
  lost, and a byte in the rest of such a message could be taken for an
  acknowledge
- A malformed message from the central unit could stall all communication
  with it
- After the central unit was unreachable for a while, commands were delayed
  by about as long as the outage lasted
- A command sent while the bridge was reconnecting started a second
  connection next to the reconnect
- Connection attempts to an unreachable or still booting central unit no
  longer leave sockets open
- The total of a pulse counter no longer turns negative above 2^31 pulses
- Long-press input messages work in the native image
- A relay, flag, mood or timed function configured as `binary_sensor` (with
  `type` or `hatype`) no longer stays `unknown` in Home Assistant
